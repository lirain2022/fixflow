# FixFlow 完整整合計畫

目標：在現有 Java 21 / Spring Boot 與 React 專案完成可展示的報修生命週期，資料由後端保存，角色權限由伺服器執行。

依據：使用者提供的 FixFlow 藍圖、`要做的核心系統說明.md` 與目前程式。使用者已要求直接完成，本計畫作為執行紀錄，不再逐項要求確認。

## 架構與規則

- 保留現有 Task 教學程式；正式工單另建 Ticket。
- 狀態統一採藍圖及前端既有 OPEN → ASSIGNED → IN_PROGRESS → RESOLVED → CLOSED；OPEN / ASSIGNED 可取消。核心說明中的 PENDING 視為 OPEN。
- CUSTOMER 僅能存取自己建立的工單；TECHNICIAN 僅能存取指派給自己的工單；ADMIN 可派工、改優先級及管理帳號。
- 註冊只能產生 CUSTOMER；密碼雜湊，JWT 短效，停用帳號立即拒絕既有 Token。正式設定不能使用公開示範密碼。
- 新增、派工、狀態更新、留言、附件、維修紀錄會留下歷程；結案不刪除歷史。
- SLA：CRITICAL 2 小時、HIGH 4 小時、MEDIUM 24 小時、LOW 72 小時。統計由資料庫計算，Redis 選用快取。
- local 使用獨立 H2；正式使用 PostgreSQL / Flyway；原 Task 資料不自動搬移。AI 按原藍圖列第二階段。
- 本機示範完整交付；外部雲端部署需使用者自己的主機及憑證，不自動發布。

## 實作順序與驗收

1. **身份與資料基礎**：User、DTO、JWT、Security、錯誤格式、Flyway。HTTP 測試註冊、登入、錯誤密碼、越權註冊、匿名拒絕。
2. **工單流程**：Ticket、查詢分頁、派工、轉態、維修、留言、歷程、SLA、附件。HTTP 測試完整三角色流程、跨客戶隔離、非法轉態、無效輸入、附件存取與重複操作。
3. **管理與統計**：帳號列表/停用、技師清單、Dashboard、Redis 快取。驗證管理端限制及停用 Token。
4. **React 串接**：登入註冊、列表/篩選/新增/編輯、詳細抽屜、派工、維修、留言/圖片、管理員畫面及 Dashboard。保留既有視覺語言與手機版；API 失敗顯示錯誤，不退回假資料。
5. **交付**：啟動腳本、環境變數範本、Docker、CI、API 文件、操作與面試說明。執行後端測試、前端測試/build、三角色真實瀏覽器驗收。

## 重要邊界

- 不把瀏覽器 localStorage 的展示工單當正式資料自動匯入。
- 前端不決定角色、工單擁有人或可轉換狀態；後端再次驗證。
- 附件限圖片、限制大小並檢查格式；只能透過授權 API 下載。
- 並行更新以資料庫鎖/版本避免覆蓋；工單流水號由資料庫 ID 產生避免衝突。
- 安裝套件、權限或環境故障需記錄實際結果，不把尚未完成的工作標示通過。
