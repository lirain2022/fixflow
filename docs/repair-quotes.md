# 維修報價確認

管理員開啟會員建立的工單，在「維修報價」展開後按「建立報價」，填寫預估人工費、零件費與維修範圍。會員會收到站內通知；開啟工單即可同意報價或提出問題。預估金額以 NT$ 顯示，不會自動付款或寫入實際費用。

重新報價會新增版本，舊版的金額、說明與回覆都保留。會員必須確認最新版本；過期畫面、重複點擊與同時報價會被阻擋。收到問題後，管理員可修改說明或金額，重新送出供會員確認。

已有報價的工單需同意最新報價才能開始或提交維修完成；派工及儲存費用草稿仍可操作。沒有報價的舊工單沿用原流程。內部管理員自己建立的工單不會進入會員報價流程。會員有尚待確認／重新報價的有效工單時，不能停用帳號，避免無法完成確認。

報價與實際費用分開：同意報價不是付款，也不是費用上限鎖定。最終金額仍由維修紀錄登錄，會員在驗收時可查看；如費用改變，應先重新報價確認。此版本未實作付款、電子簽章、報價效期或自動超額審核。

## 資料與接口

V7 新增 ff_repair_quotes，不修改既有資料列或 V1–V6 遷移。更新前停止後端並備份資料庫，啟動時 Flyway 套用 V7。只驗證本機 H2；其他正式資料庫仍需部署前驗證。

- GET /api/tickets/{id}/quotes：管理員查看報價。
- POST /api/tickets/{id}/quotes：送出新版本；previousQuoteId 必須符合現有最新版（第一次為 null）。
- GET /api/member/tickets/{id}/quotes：本人查詢。
- POST /api/member/tickets/{id}/quotes/respond：以 quoteId、version、decision、message 回覆；decision 為 ACCEPTED 或 CHANGES_REQUESTED。

費用各限 0–9999999999.99，最多兩位小數；說明／問題最多 2000 字。後端使用 BigDecimal 計算，API 以小數字串傳遞。帳號停用與送出報價採會員→工單鎖順序；回覆及維修狀態轉換使用同一工單鎖，避免並行狀態不一致。
